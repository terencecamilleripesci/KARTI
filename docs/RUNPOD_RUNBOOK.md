# KARTI — RUNPOD RUNBOOK
**The day you rent the GPU. Follow it top to bottom. Do not think, just run.**

Total expected: **~40 minutes on the clock, well under €1.**
Everything that needs deciding has already been decided. If something looks wrong,
§6 tells you within two minutes, not sixty.

> ### Reminder before you start
> We generate the **art-window picture only** — never a whole card. No frames, no
> borders, no names, no ATK/DEF, no text. The game draws the card around the art in
> HTML/CSS, which is exactly what lets you nerf a card or rewrite a joke later
> without touching the art. This is already baked into every prompt.

## 0. Before you rent anything (do this on the Pi, the day before)

```bash
cd /home/foxhound/webclients/karti-malta
node scripts/make_prompts.js --check
```

Read the report. You want:

- `STILL NEEDING A LOOK : 0` — no card can trip the safety filter
- `weak subjects … count: 0` — no card is too abstract to draw
- `unique filenames … OK` and `cards -> art files … OK 1:1`

Then **skim `art/prompts.txt`.** It is the whole point of that file. Anything that
reads like it would generate rubbish, add the card id to `SUBJECT_OVERRIDES` near the
top of `scripts/make_prompts.js` with a concrete thing to draw, and re-run. Fixing a
prompt now is free. Fixing it after the pod is another rental.

When you are happy:

```bash
node scripts/make_prompts.js        # writes art/prompts.jsonl, prompts.txt, MANIFEST.md
```

Set 3 (`js/set3.js`, KRT-03 *Festa Kbira*) has landed, so this is **200 cards + 35 UI
= 235 images**. If a Set 4 appears before the rental, just re-run the command — new set
files are discovered, set-tagged and prompted automatically. You do not need to edit
anything.

## 1. Which pod to rent

| | |
|---|---|
| **GPU** | **1 × RTX 4090** (24 GB) |
| **Cloud** | **Community Cloud** — this job is stateless and resume-safe, so an interruption costs you one image |
| **Template** | *RunPod PyTorch 2.x* (any recent CUDA 12 PyTorch template) |
| **Container disk** | **50 GB** |
| **Volume** | none — do not attach one, it keeps billing after you stop |
| **Ports** | SSH only. You do not need a web UI. |

**Why the 4090.** SDXL at 1024×1024 is not compute-bound enough to benefit from an
A100, and an A100 costs 2–4× more per hour. The 4090 is the cheapest card that runs
SDXL fp16 comfortably in VRAM at batch 4. An A5000 is cheaper per hour but roughly
half the speed, so it costs *more* for this job and takes twice as long. An L40S or a
5090 also work fine if no 4090 is free — the script does not care.

**Why 50 GB.** PyTorch image ~20 GB + the SDXL checkpoint ~7 GB + ~350 MB of output +
headroom. 20 GB will fill up mid-run and waste the rental.

**Model / checkpoint:** `RunDiffusion/Juggernaut-XL-v9` — SDXL-class, excellent prompt
adherence, holds a strong stylised look. If it fails to download for any reason the
script falls back to `stabilityai/stable-diffusion-xl-base-1.0` on its own and keeps
going. **Use one checkpoint for the whole batch.** Switching mid-run means two visually
different games.

## 5. The 5-image style check — DO NOT SKIP THIS

```bash
python3 scripts/runpod_batch.py --limit 5
```

First run also downloads the checkpoint (~7 GB, about a minute on RunPod's network).
Then pull them straight back to the Pi and **look at them**:

```bash
# on the Pi
scp -P <port> 'root@<pod-host>:/workspace/karti/art/raw/*.png' /tmp/karti-check/
```

### The two-minute verdict (from `docs/ART_STYLE_BIBLE.md` §8)

| Check | Fail means |
|---|---|
| Shrink one to 96 px — can you still tell what it is? | style is too detailed → **stop** |
| Thick black outline, flat cel shading, no soft gradients? | wrong checkpoint or CFG → **stop** |
| Five hues or fewer, attribute colour clearly present? | CFG too low → try `--cfg 7` |
| One subject, centred, nothing important near the edges? | **stop** and loosen the framing |
| **Any text, numbers, signature, border or card frame anywhere?** | **stop immediately** — see below |
| Does it look like KARTI, or like generic stock art? | **stop** |

**Two fails = stop and fix before generating 230 more.** That is what this step is for.

### Fixes, in the order to try them

| Symptom | Fix |
|---|---|
| Text / letters appear in the image | raise CFG: `--cfg 7.0`. If it persists, the checkpoint is fighting you — `--model stabilityai/stable-diffusion-xl-base-1.0` |
| A card **frame or border** is being drawn | same fix. Then re-check — this is the one thing we will not ship |
| Too painterly / soft / photographic | `--cfg 7.0`, and confirm you are on Juggernaut v9, not a realism checkpoint |
| Washed out, burnt colours | lower it: `--cfg 5.5` |
| Composition too tight, heads cropped | regenerate with `--variants 2` and pick the looser take later |
| One specific card is just wrong | leave it — collect it in a reject list and re-run it in §7 |

Anything you change here, change it for the **whole run**. Never half a batch in one
setting and half in another.

Once you are happy, wipe the 5 test images so the real run regenerates them cleanly
with the settings you settled on:

```bash
rm -f /workspace/karti/art/raw/*.png
```

## 6. The real run

```bash
cd /workspace/karti
python3 scripts/runpod_batch.py 2>&1 | tee run.log
```

It prints a line per batch with elapsed time and a live ETA. Leave it alone.

- **All P1 finishes before any P2 starts** — if you have to bail early, you still have
  a complete-looking game.
- **It is resume-safe.** If SSH drops, reconnect and run the exact same command; every
  image already on disk is skipped. Nothing is lost but the image in flight.
- Failures are retried once, then logged and skipped. The run never aborts.
- Any failures are written to `art/raw/_failed.txt`.

Want more takes to choose from? You have the time (see §9):

```bash
python3 scripts/runpod_batch.py --variants 2
```

Variant 1 is `<id>.png`, variant 2 is `<id>__v2.png`. Both variants of every P1 asset
are done before any P2 starts.

---

## 7. Re-run just the rejects

While it runs, keep a text file of any ids you do not like. Then:

```bash
# a few, by name
python3 scripts/runpod_batch.py --only petard,kunjata,statwa --force

# a lot, from a list
printf 'petard\nkunjata\nstatwa\n' > rejects.txt
python3 scripts/runpod_batch.py --only-file rejects.txt --force

# whatever failed on its own
python3 scripts/runpod_batch.py --only-file art/raw/_failed.txt --force
```

`--force` is what makes it overwrite; without it, resume-safety would skip them.
To get a *different* picture for a card rather than the same one again, add
`--variants 2` and pick the alternate later with `postprocess.py --pick`.

## 8. Download, then KILL THE POD

```bash
# on the pod — one file is far faster than 235
cd /workspace/karti && tar czf karti-raw.tgz art/raw run.log

# on the Pi
cd /home/foxhound/webclients/karti-malta
scp -P <port> root@<pod-host>:/workspace/karti/karti-raw.tgz .
tar xzf karti-raw.tgz && rm karti-raw.tgz
ls art/raw/*.png | wc -l          # must match the number in the run summary
```

> **Optional, saves ~90 % of the download.** `postprocess.py` is pure Pillow and runs
> anywhere. `scp` it to the pod, run it there, and `tar` up `art/*.jpg` + `art/ui/`
> instead — ~30 MB instead of ~350 MB.

### ⛔ NOW KILL THE POD ⛔

**RunPod console → your pod → `Terminate`. Not "Stop". TERMINATE.**

- **Stop** keeps the container disk and **keeps billing you** for storage.
- **Terminate** deletes it and billing ends.
- Confirm the pod is gone from your list. Refresh the page and look again.
- You have the tarball on the Pi. There is nothing left on that pod you need.

**Do not go to bed with a pod running.** An idle 4090 left overnight costs more than
the entire job.

## 9. Time and cost — the maths

**Assumption: 5.0 seconds per image, wall clock.**
RTX 4090, SDXL 1024×1024, 30 steps, DPM++ 2M Karras, fp16, batch 4. A 4090 does
roughly 8–11 iterations/second at 1024² in fp16, so 30 steps ≈ 3.0–3.7 s, plus VAE
decode and PNG write ≈ 0.4 s → **3.5–4.1 s realistic**. Rounding up to **5.0 s** gives
about 25 % headroom for thermal throttling and a noisy neighbour on the host.

### → **~720 images per GPU hour.**

| Job | Images | Generation time |
|---|---:|---:|
| Card art only (200 cards) | 200 | **16.7 min** |
| **Everything — 200 cards + 35 UI** | **235** | **19.6 min** |
| 200 cards + UI, **2 variants each** | 470 | **39.2 min** |
| 200 cards + UI, **3 variants each** | 705 | **58.8 min** |

### Full session, at the 200-card target

| Step | Time |
|---|---:|
| Pod deploy + boot | 3 min |
| `pip install` | 2 min |
| Upload prompts, dry-run | 1 min |
| Checkpoint download (~7 GB) | 1.5 min |
| 5-image style check + look at them | 4 min |
| **Main run, 235 images** | **19.6 min** |
| Re-run ~15 rejects | 1.5 min |
| Tar + download + terminate | 5 min |
| **TOTAL ON THE CLOCK** | **≈ 38 min** |

### Cost

RunPod bills by the second. Check the live price when you deploy — these are the
typical ranges:

| GPU | Typical $/hr | 38 min costs | Verdict |
|---|---:|---:|---|
| **RTX 4090, Community** | **$0.34 – 0.44** | **$0.22 – 0.28** | ✅ **pick this** |
| RTX 4090, Secure | $0.69 | $0.44 | fine if Community is empty |
| L40S / 5090 | $0.86 – 1.10 | $0.55 – 0.70 | fine, no faster for SDXL |
| A100 80 GB | $1.19 – 1.89 | $0.75 – 1.20 | ❌ paying for VRAM you cannot use |
| RTX A5000 | $0.22 – 0.26 | ~$0.35 | ❌ cheaper/hr but ~2× slower = costs more |

> ### Budget: **under $0.50.** Even a full billed hour on a 4090 is under $0.70.
> Set a €5 spend cap on the account and you cannot get hurt.

### "Could we art more cards in the same hour?"

**Yes — enormously.** 235 images is **20 minutes of a 60-minute rental.** At 720
images/hour you could, in one single rental:

- do all 200 cards + all 35 UI assets, **and** have **3 variants of every single one**
  to choose from later (59 min), **or**
- do all 235 at 2 variants (39 min) and still have **20 minutes / ~240 images spare**, **or**
- art **up to ~700 cards** in total — Sets 4, 5 and 6 as well, if they were written.

**Recommendation: run `--variants 2`.** It costs ~20 extra minutes and about 15 cents,
and it means every card you dislike already has a second take sitting on disk instead
of needing another rental. That is the single best use of the spare time.

The real constraint is not GPU hours — it is **written cards**. Card text is the
bottleneck, not art. If Set 3 is not finished on the day, generate what exists; the
scripts pick up new sets automatically and a second rental for Set 4 will cost another
20 cents.

## 10. Back on the Pi

```bash
cd /home/foxhound/webclients/karti-malta
python3 scripts/postprocess.py
```

This crops each raw to the shape the game needs, resizes, compresses, strips all
metadata, cuts real transparency for the packs / glows / icons, derives
`icons/icon-192.png`, `icons/icon-512.png` and `art/ui/og.jpg` for free, and prints the
total MB with an extrapolation to 200 cards.

**Target: well under 100 MB. Expect ~30 MB.**

Prefer the alternate take on a card:

```bash
python3 scripts/postprocess.py --pick petard=2 --only petard --force
```

Then keep the raws **out of the Pages repo** — they are ~350 MB of working files:

```bash
echo 'art/raw/' >> .gitignore
```

Ship: `art/*.jpg`, `art/ui/*`, `icons/*`. That is it. Done.
