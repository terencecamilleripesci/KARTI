# KARTI — ASSET LIST
**Everything that has to come off the GPU. Nothing gets discovered missing while the pod is running.**

Companion docs: `docs/ART_STYLE_BIBLE.md` (the look) · `docs/RUNPOD_RUNBOOK.md` (the day)
Live machine-readable inventory: **`art/MANIFEST.md`** and **`art/prompts.jsonl`**,
both regenerated by `node scripts/make_prompts.js`.

---

## 0. THE RULE THAT GOVERNS EVERY IMAGE HERE

> ## We generate the **art-window image only**. Never a whole card.
>
> No card frame. No border. No name bar. No level stars. No attribute badge.
> No ATK/DEF box. No rarity gem. No set symbol. **No text of any kind.**
>
> `css/cards.css` renders the entire card in HTML *around* the art. That is
> deliberate: it means a card can be **nerfed, renamed, re-joked, re-costed or
> completely restyled without regenerating a single image**. Art and data stay
> decoupled forever.

The same rule applies to the UI art: we generate raw **backgrounds, textures,
pack illustrations and portraits**, never a mock-up with a title baked in. Every
piece of lettering in KARTI — the wordmark, button labels, "YOU WIN", pack names,
currency amounts — is CSS text or SVG, produced separately and never generated.

This is enforced in three places, on purpose:
1. positively in every prompt (`ART_ONLY` in `scripts/make_prompts.js`),
2. in the shared negative prompt (`border, frame, card frame, nameplate, stat box, text, …`),
3. in `scripts/postprocess.py`, which only ever crops, resizes and compresses.

## 2. Card art — the rule, not a list of 200 rows

There is deliberately **no hand-maintained table of cards here.** It would be stale
within a day. The inventory is generated from the card data itself:

| | |
|---|---|
| **Source of truth** | `js/cards.js`, `js/set2.js`, `js/set3.js`, … (auto-discovered) |
| **One art file per card, always** | `art/<card.id>.jpg` |
| **Raw generation** | `art/raw/<card.id>.png` · 1024 × 1024 |
| **Shipped** | **768 × 768 JPEG**, quality 82 → stepped down to stay ≤ 160 KB |
| **Aspect** | **1 : 1 square** (reasoning in §3) |
| **Transparency** | No — the art window is always fully covered |
| **Priority** | **P1**, every card |
| **Seed** | deterministic from the card id — same card, same picture, forever |
| **Budget** | target **≤ 120 KB**, hard cap **160 KB** per card |

Regenerate the full per-card inventory any time:

```bash
node scripts/make_prompts.js          # -> art/MANIFEST.md, art/prompts.txt, art/prompts.jsonl
node scripts/make_prompts.js --check  # counts, integrity, content-filter flags
```

`--check` proves **one card → exactly one art file, no id or filename collisions**
before a cent of GPU time is spent.

### Prompt composition per card
Assembled automatically from the card's own data:

```
[type framing] + [card name] + [visual half of the joke, mechanics stripped]
+ [attribute palette]  (from card.f, locked to ATTR.c)
+ [rarity drama]       (from card.r — light and angle, never colour)
+ [composition rules]  (centred, safe margins)
+ [locked style block] (ART_STYLE_BIBLE §2)
+ [ART_ONLY: no frame, no border, no text]
```

Anything the automation would render badly gets a hand-written subject in
`SUBJECT_OVERRIDES` in `scripts/make_prompts.js`. **28 cards** currently use one —
17 to route around safety-filter trigger words (drunk, beer, whisky, rifle, naked,
police, axe…), 11 because the joke was too abstract to draw. `--check` reports any
card still needing attention; it currently reports **zero** on both counts.

## 3. Why card art is square — measured, not guessed

`.card__art` is `flex: 1`, so the art window's shape changes with the length of the
joke text *and* with the card size. Measured in headless Chromium against the real
`css/cards.css`:

| Card size | Art window (px) | Aspect |
|---|---|---|
| `.card--sm` — browse grid tile | 95.8 × 109.8 → 95.8 × 95.9 | **0.87 – 1.00** |
| `.card--md` — card in hand | 157.7 × 119.1 → 157.7 × 111.7 | **1.32 – 1.41** |
| `.card--lg` — full card view | 276 × 211 → 276 × 198 | **1.31 – 1.39** |

The image is drawn with `object-fit: cover`, so **one file is centre-cropped three
different ways**. A square master is the only shape that survives all three:

- worst landscape window (1.412) keeps the middle **70.8 %** of the height
- worst portrait window (0.872) keeps the middle **87.2 %** of the width

→ **Safe zone = central 70 % height × 85 % width.** Every prompt reserves it
("generous empty margin on all four sides, nothing important within 15 percent of any
edge"). That is a deliberately *more* generous margin than the ~8–10 % rule of thumb,
because the landscape crop here is far more aggressive than a fixed window would be.

**768 × 768 shipped** because the largest on-screen art window is 276 CSS px wide;
768 covers that at ~2.8× device pixel ratio, which is beyond any phone that will run
this. Going to 1024 would nearly double the repo weight for pixels nobody can see.

## 5. Weight budget

| | |
|---|---|
| Card art | 768×768 JPEG q82, ladder-limited to **≤ 160 KB**, target ≤ 120 KB |
| UI art | capped at **400 KB** each (backgrounds are allowed to be heavier) |
| **200 cards** | **≈ 20–24 MB** |
| All 35 UI assets | ≈ 6–8 MB |
| **Total shipped** | **≈ 30 MB** |

Well inside the 100 MB GitHub Pages soft limit — with room for three more sets.
`scripts/postprocess.py` prints the real total, the per-file heaviest offenders and
an extrapolation to 200 cards every time it runs, so this can never drift silently.

The raw 1024px PNGs (~1.5 MB each, ~350 MB for the batch) are **working files.**
Keep them off the Pages repo — archive them somewhere else, or `.gitignore` `art/raw/`.

## 6. If the hour runs short

Generate in this order — it is already the order `runpod_batch.py` uses:

1. **All card art** (P1). A game with 200 illustrated cards and a plain CSS menu looks finished.
2. **`emblem`, `cardback`, `board`, `home-bg`** — four images that make the shell feel designed.
3. **Packs + `burst` + the three rarity glows** — the opening ceremony is the game's best moment.
4. **`victory` / `defeat`, coin + dust icons.**
5. Everything in P2.

Skipping all of P2 costs nothing at launch: textures fall back to CSS gradients,
boss portraits fall back to the boss's own card art, and story mode ships later.
