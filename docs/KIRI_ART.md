## ⛔ RULE ZERO, AND WHY A PROPERTY GAME NEEDS IT MOST

**We generate the art window only. Never a finished board tile.**

Every square on this board carries a name, a Maltese subtitle, a price, a colour band,
an ownership ring, a floor count and a rent table. **Not one of those is generated.**
`js/kiri-ui.js` draws all of it in CSS on top of the picture.

On the card game this rule saves a rental when a card is renamed. On a **property**
game it saves a rental every time the rents are rebalanced — and the rents on a
property game get rebalanced. Bake "SLIEMA · €280" into a JPEG and the next balance
pass costs another GPU hour and a re-upload of thirty-two files.

So: **no lettering of any kind.** No property names, no prices, no rent tables, no
"FOR SALE" boards with writing on them, no banknote denominations, no wordmarks. Image
models render text as convincing garbage — it looks like writing until you read it.

Where a sign genuinely helps the joke (the deed, the key tag), the prompt asks for it
**blank** and the negative bans lettering. Check it on arrival: any image with legible
characters in it is an automatic reject, no exceptions.

## THE 77-TOKEN WALL

CLIP takes 77 tokens and **silently bins the rest**. The first KARTI run came back as
oil paintings and photographs because the entire style block sat past the cutoff.

`scripts/make_kiri_prompts.js` assembles every prompt through the same `fitPrompt()`
budget as `scripts/make_prompts.js` (74 tokens, style first) and then **checks its own
work**:

```
node scripts/make_kiri_prompts.js --check
```

```
  images            : 29
  P1 / P2           : 19 / 10
  alpha cut-outs    : 7
  unique ids        : OK
  unique filenames  : OK
  filename-safe ids : OK
  over 74 tokens    : OK — nothing is being binned
  asks for lettering: OK
  subject trimmed   : OK — every subject survives whole
  longest prompt    : 71 tokens
```

`subject trimmed` is the one people miss. `fitPrompt()` will happily shorten an
over-long clause to make the budget, and a subject cut off halfway — *"...one bored dog
on"* — gives the model a fragment to illustrate and it draws nothing coherent. The
check fails the build rather than letting that through. If it ever trips, **shorten the
`subject` in the script**; do not raise the budget.

## THE STRATEGY: 29 IMAGES, NOT 70

There are 32 squares and 36 cards. A picture for each would be 68 images, each seen
once, each a download on somebody's phone.

Instead every image is **reused**, and the reuse is keyed to something the player
already understands:

| The trick | Covers |
|---|---|
| **6 locality washes**, one per colour group | all **16 properties** — the group already IS a place |
| **7 fate illustrations**, two deck faces + five outcomes | all **36 cards**, keyed by what the card *does* |
| **1 transport image**, **1 services image**, **1 tax image** | 4 + 2 + 2 = **8 squares** |
| **4 corner scenes** | the 4 corners |

Six strong pictures of Marsa, Ħamrun, Birgu, Swieqi, Sliema and Valletta *are a place*.
Sixteen weak ones are a sticker sheet. And a new card written next month needs **no new
art** — it inherits the picture for its action.

**Not repeated here** (already in `docs/RUNPOD_PARTY.md`, generate them there):
- `logo-kiri` — the hub tile
- `coin-face` / `coin-back` — the KARTI coin. **IL-KIRI's money is that coin.** No
  banknote art is requested and none should be: banknotes are made of numbers, and
  numbers are the one thing a model cannot draw.

## HOW THE GAME CONSUMES THEM — the swappable slot

**IL-KIRI ships complete with zero images.** Every visual is a finished CSS object
first. The picture is a second layer that starts at `opacity: 0` and is only ever
revealed by a real `load` event on an `Image()`:

```js
/* js/kiri-ui.js — artWash() */
const img = new Image();
img.onload  = () => { layer.style.backgroundImage = 'url(' + src + ')';
                      layer.style.opacity = '1'; };
img.onerror = () => { /* nothing. the CSS underneath is the design. */ };
img.src = src;
```

Consequences, all deliberate:

- A missing file is **invisible**, never a broken-image icon and never a blank panel.
- Art can be added **one file at a time** — drop `kiri-loc-sliema.jpg` in and Sliema
  gets a photograph of itself while the other five groups stay CSS. Nothing to rebuild.
- The board itself **never** loads art per square. Thirty-two images at 44 points would
  be thirty-two requests to render a map that is already legible as colour bands and
  codes. The board stays CSS forever; the art lives in the sheets, where there is room
  to see it.
- Squares are identified on the ring by a **CSS short code** (`GRX`, `SLM`, `KJU`), not
  by an emoji, because plenty of devices have no colour emoji font and a board of
  identical grey boxes is not a board.

## ACCEPTANCE — check these before you shut the pod down

1. **No lettering.** Zoom in on `kiri-deed`, `kiri-tok-key` and `kiri-sq-tax` — those
   three ask for objects that normally carry writing. Any legible character = reject.
2. **`kiri-deed` must be blank.** If the model has written on the deed, regenerate with
   `blank` pushed earlier in the subject.
3. **The washes must be quiet in the middle.** `kiri-loc-*`, `kiri-board-felt` and
   `kiri-hero` all have UI on top of them. A subject dead-centre fights the text.
4. **The alpha seven must sit on flat black.** `kiri-tok-*`, `kiri-build-*`,
   `kiri-deed`. Anything with a ground plane or a cast shadow will key badly — the
   negative bans both, but check.
5. **One checkpoint for the whole batch.** Switching model mid-run gives you two
   visually different games.

## RUN IT

```bash
# on the Pi, the day before
node scripts/make_kiri_prompts.js --check     # must be all OK
node scripts/make_kiri_prompts.js             # writes the three files
less art/kiri-prompts.txt                     # skim it. this is the point of that file.

# on the pod (see docs/RUNPOD_RUNBOOK.md §3–§5)
scp -P <port> art/kiri-prompts.jsonl root@<pod>:/workspace/karti/art/
python3 scripts/runpod_batch.py --prompts art/kiri-prompts.jsonl --dry-run
python3 scripts/runpod_batch.py --prompts art/kiri-prompts.jsonl
```

29 images at ~9 s each on a 4090 is **under five minutes of GPU time**. It is the
cheapest part of the whole rental — which is exactly why it is worth reading
`art/kiri-prompts.txt` properly first.
